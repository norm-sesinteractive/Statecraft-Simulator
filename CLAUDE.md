# Statecraft Simulator

A mobile-first strategy simulation in Unity. The player is a hidden, Illuminati-like society that steers
nations through their institutions (media, education, law and order, politics) and never gives a direct
order. Controls stay simple; outcomes are complex. The fantasy is shaping the flow of a river, not
micromanaging (explicitly not Civilization). Norm's original pitch, verbatim: [Docs/design/PITCH.md](Docs/design/PITCH.md).

Current state, loose ends and next steps (always loaded):

@Docs/STATUS.md

## Tech facts

- Unity **6000.3.13f1**, URP 17.3 (Universal 3D template: Mobile and PC renderer assets), Input System, UI Toolkit.
- Platform: **mobile first** (Android, then iOS), PC later. Touch-first, landscape (orientation provisional).
- The simulation is **pure C#** (`Statecraft.Sim`, `noEngineReferences: true`), deterministic, 1 tick = 1 month.
  Assemblies, patterns and conventions: [Docs/architecture/ARCHITECTURE.md](Docs/architecture/ARCHITECTURE.md).
- `Tools/Headless` compiles the same sim and test sources with the .NET SDK, so sim work builds and tests in
  seconds **with the Unity editor open**. Details: [Docs/architecture/TOOLING.md](Docs/architecture/TOOLING.md).

## Hard rules (do not break without Norm's say-so)

1. **Docs are the source of truth.** Read the owning doc before designing or coding; update it in the same
   session as the change ([Docs/DOCS_GUIDE.md](Docs/DOCS_GUIDE.md)). Log decisions in `Docs/decisions/`,
   including Claude's own proposals (status `Proposed`).
2. **The sim never touches Unity.** Game and UI code read sim state and send commands; they never mutate it.
3. **Norm runs every git write** (init, add, commit, push, remotes). Claude may run read-only git
   (`status`, `log`, `diff`) and hands over copy-paste commands for the rest, one per bash block.
4. **Main checkout only.** No git worktrees or side branches; Unity only watches this folder.
5. **In-game text is Norm's.** Player-facing text Claude adds is an obvious placeholder (`[NATION_1]`,
   `[EVENT_TITLE]`), and the session summary lists every placeholder added. Dev-only tooling (the dev HUD,
   editor menus, logs) may use plain technical English (D-0015, proposed).
6. **ASCII only in UI strings, UXML and USS.** Unicode glyphs render as boxes on device fonts. Real icons are
   PNGs that Norm makes on request: name the asset you need.
7. **Placeholder art only.** Claude builds visuals from Unity primitives; Norm makes production meshes in
   Blender. `.blend` files never enter git (`ArtSource/` is ignored); exported FBX and PNG go under `Assets/Art/`.
8. **Never quote a serialized default as the live value.** Scenes are generated by `MainSceneBuilder`, so
   values live in that code; still grep the scene or asset before stating a live value.
9. **Screen-space sizes are fractions of the 1080 px reference height**, never raw device pixels.
10. **No em dashes** in anything authored for this project: docs, code comments, commit messages, chat.

## Session workflow

- **Start:** a SessionStart hook prints a brief: git state, whether the editor holds the project, docs drift,
  doc lint. For a fuller orientation after a break, run `/catch-up`.
- **During:** docs move with the code. Record decisions with `/decide`. Settle design questions with Norm
  through `/design-review`. Path-scoped rules in `.claude/rules/` load when you touch sim, Unity or doc files.
- **End:** `/wrap-up` regenerates the generated docs, updates STATUS, WORKLOG, ROADMAP and decisions, lints,
  and hands Norm the git commands. Hooks remind both of you when code has moved ahead of the docs.

## Verify (cheapest check that covers the change)

- Sim and its tests (editor may stay open, seconds): `dotnet test Tools/Headless/Statecraft.Headless.slnx --nologo -v q`
- A model experiment: `dotnet run --project Tools/Headless/Runner -- run --script wrath-media --years 60`
- Unity-side code (Game, UI, Editor), editor may stay open (seconds): `dotnet build Statecraft.Editor.csproj -v q --nologo`
  (Unity-generated project file; a brand-new .cs file is missing from it until Unity regenerates, see TOOLING.md)
- Unity compile, edit-mode tests, or settings and scene rebuild (editor must be closed, minutes):
  `powershell -ExecutionPolicy Bypass -File Tools/unity.ps1 -Mode compile` (or `test`, `setup`)
- Everything at once: `powershell -ExecutionPolicy Bypass -File Tools/verify.ps1` (add `-Unity` when the editor is closed)
- Claude cannot run the game. Norm verifies in the editor and on device; say when a change needs a device check.

## Working with Norm

- Surface design decisions and tradeoffs before non-trivial work; do not guess intent. Mark proposals
  `[PROPOSED]` and log them.
- Diagnose before fixing. When a cause is uncertain, propose instrumentation first; after one failed fix on
  something Norm can see, offer the diagnostic and the revert together.
- Use cheaper subagents (Sonnet, Haiku) for reading, grepping, verifying and mechanical drafting; keep
  synthesis and decisions on the main model. About five heavy agents per wave.
- Describe colors in hex (`#D94436`). Offer token-saving alternatives when they are significant.
- Flag stale comments and dead code in chat; do not silently delete them.
- Claude's memory holds only Norm's profile and working style. Project knowledge lives in this repo.
